# C4-OE Cortical Bulk RNA-seq

Analysis of the bulk RNA-seq differential expression pipeline
for *Sánchez-Carbonell, Bolshakova, Ávila-Pagán et al.*, "Sparse Neuronal C4 Elevation
Induces Network-Wide Transcriptomic and Lipid-Droplet Remodeling in the
Cortical Microenvironment" (bioRxiv, 2025.05.29.656749).

The analysis has three strands, all driven from a single entry point
(`run_full_analysis.R`): bulk RNA-seq differential expression, a cross-species
comparison against the human schizophrenia synapse proteome, and a projection of
the differential-expression signature onto a single-cell cortical reference.

## Repository layout

```

                  third-party files are obtained separately (see Input files/README.md)
Outputs/          All results, one folder per strand. Git-ignored and fully
                  regenerated by a run (see Outputs/README.md)
scripts/
  00_setup/                          dependency install, environment check, renv snapshot
  01_bulk_rnaseq_DE/                 QC → DESeq2 → GO ORA/GSEA → WGCNA
    00_config.R                          paths, thresholds, sample metadata
    01_load_data_and_infer_sex.R         load counts, map symbols, infer sex
    02_differential_expression_deseq2.R  DESeq2 (design: ~ sex + genotype)
    03_go_enrichment_ORA_GSEA.R          GO ORA (with universe) + GSEA
    04_coexpression_wgcna.R              WGCNA modules + per-module GO
    run_all.R                            runs strand 01's four steps in order
    R/functions.R                        all reusable functions, documented
  02_cross_species_comparison/       mouse C4-OE vs human SCZ synapse proteome
  03_scRNAseq_reference_projection/  DEG projection onto an Allen single-cell reference

```

The full output tree is documented in
[`REPRODUCIBILITY.md`](REPRODUCIBILITY.md) and [`Outputs/README.md`](Outputs/README.md).

## Running the scripts (working-directory notes)

Every script locates its own files by figuring out **where it lives on disk**,
not by assuming anything about your current working directory. So all of
these work interchangeably:

- Clicking "Source" on any of the numbered scripts in RStudio.
- `Rscript scripts/01_bulk_rnaseq_DE/run_all.R` from a terminal at the repo
  root.
- `source("scripts/01_bulk_rnaseq_DE/01_load_data_and_infer_sex.R")` from an
  R console, regardless of `getwd()`.

If you ever see a "cannot open file ... Input files/raw_counts.csv" error
with a path that looks doubled-up or missing a folder level, it means the
script was sourced in a way that couldn't auto-detect its own location
(rare, but possible with some remote/notebook execution setups) — in that
case, `setwd()` to the repo root first, or check that you're sourcing one of
the numbered scripts / `run_all.R` (not, e.g., copy-pasting individual lines
into a fresh console without sourcing the whole file).

## Group naming

The two experimental groups are labelled **Control** (wild-type) and
**C4-OE** (C4 overexpression) in every figure, table, and message the
pipeline produces.

Note for anyone reading the code: the `sample` column in `00_config.R` keeps
the original `WT_` / `mC4_` prefixes because those are the literal column
headers inside `raw_counts.csv` and must match for the counts matrix to be
indexed correctly. Internally the genotype factor levels are `Control` and
`C4_OE` (underscore) because a hyphen is not a syntactically valid R name —
DESeq2 silently mangles such factor levels when building the model matrix,
which would break `resultsNames()` lookups. Conversion to the display labels
`Control` / `C4-OE` and `Control_10` / `C4-OE_4` happens at plot and table
write time via `display_genotype()` and `display_sample()` in
`R/functions.R`. To change the labels, edit `GENOTYPE_DISPLAY` and
`CONTRAST_LABEL` in `00_config.R` — nothing else needs touching.

## How to reproduce

Everything runs from a single entry point at the repo root:

```r
# 1. Restore the exact package versions used to produce these results
renv::restore()

# 2. (optional) confirm the environment matches
source("scripts/00_setup/check_environment.R")

# 3. Run the whole analysis (all three strands)
source("run_full_analysis.R")
```

`run_full_analysis.R` validates the inputs up front, creates the output tree,
runs the three strands in dependency order — each in its own R session — and
writes a provenance record to `Outputs/_provenance/`. Expect roughly 30–60
minutes, dominated by WGCNA and the GSEA permutations. To run one strand only:

```r
RUN_STRANDS <- c("01")   # "01", "02", or "03"
source("run_full_analysis.R")
```

**Inputs.** `raw_counts.csv` is included in the repository. The remaining inputs
are not — they are large or belong to other publications — so place them in
`Input files/` as described in [Input files/README.md](Input%20files/README.md):
the six MSigDB `.gmt` collections (mouse, v2023.2), the three Aryal et al.
supplementary workbooks under `cross_species/`, and the single-cell reference
`sc_data_C4OE_PCA.rds`. `run_full_analysis.R` checks each one and names anything
missing before doing any work. If the single-cell reference is absent, strand 03
is skipped and strands 01–02 still complete.

**Outputs.** Each strand writes to its own folder under `Outputs/` — see
[Outputs/README.md](Outputs/README.md) for the file-by-file manifest. Barplots
are written only where at least one term passes `p.adjust < 0.05`, so some
tables legitimately have no matching figure.

For full reproducibility details — what is pinned (package versions via
`renv.lock`, the Ensembl release, the frozen ortholog table, random seeds) and
how to verify a run — see [REPRODUCIBILITY.md](REPRODUCIBILITY.md).
